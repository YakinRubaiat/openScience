One real integrity issue was found and fixed: **SQLite foreign-key constraints were not enforced** (`PRAGMA foreign_keys` defaults to OFF per connection), so dangling FKs (e.g. a `sessions` row pointing at a non-existent user) were silently accepted. Fixed in `src/openscience/api/database.py` by enabling the pragma on every pooled connection; both ORM and raw-SQL FK inserts are now rejected as expected.

## Test 8: Database constraints

**Goal:** verify UNIQUE, NOT NULL, and FOREIGN KEY enforcement.

**Queries:**
```sql
INSERT INTO users (...) VALUES (...);          -- duplicate username  → UNIQUE violation
INSERT INTO users (... hashed_password=NULL);  -- NOT NULL violation
INSERT INTO sessions (... owner_id='ghost');   -- FK violation (PRAGMA foreign_keys=ON)
INSERT INTO sessions (... name=NULL);          -- NOT NULL violation
```

**Checks / results (after fix):**
- UNIQUE username enforced: `IntegrityError: UNIQUE constraint failed: users.username` ✅
- NOT NULL `hashed_password` enforced: `NOT NULL constraint failed: users.hashed_password` ✅
- `PRAGMA foreign_keys` on pooled connection = **1** (was **0** before the fix) ✅
- FK violation `FOREIGN KEY constraint failed` now raised at driver level ✅
- NOT NULL `sessions.name` enforced ✅
- ORM insert with dangling FK rejected ✅

### ⚠️→✅ Issue found and fixed: SQLite FK enforcement was off

- **Problem:** SQLite ships with `PRAGMA foreign_keys` OFF and it must be enabled **per connection**. The engine in `openscience/api/database.py` never set it, so `FOREIGN KEY` constraints in the schema (e.g. `sessions.owner_id → users.id`, `tasks.session_id → sessions.id`) were parsed but never enforced — orphaned rows could be inserted at the raw-SQL level, and even ORM `SessionModel(owner_id='no-such-user')` committed silently.
- **Fix** (`src/openscience/api/database.py`): register a connect listener on SQLite engines:
  ```python
  @event.listens_for(engine, "connect")
  def _set_sqlite_pragma(dbapi_connection, _connection_record):
      cursor = dbapi_connection.cursor()
      cursor.execute("PRAGMA foreign_keys=ON")
      cursor.close()
  ```
- **Status after fix:** `PRAGMA foreign_keys = 1` on pooled connections; both raw-SQL and ORM dangling-FK inserts raise `IntegrityError`. Full experiment suite re-run: still 10/10, and the pre-existing `pytest tests/` suite (excluding the independently-broken `tests/api/`) still passes 185/185 — no regressions.
